米游币兑换网页 ​

独立网页管理商品与兑换预约，复用 Lotus 已绑定的 profile、Cookie 和设备信息。机器人只负责发放专属入口和通知兑换结果。

打开页面 ​

私聊机器人发送 #米游币兑换 或 #米游币商城，打开返回的专属链接。链接 10 分钟内有效，只能使用一次；浏览器登录会话默认保留 8 小时。不要转发该链接。页面只允许查看和操作当前 QQ 自己的 profile，不向浏览器返回 Cookie、stoken 或设备凭据。

群里触发只会提示私聊，不在群内发布登录链接。机器人重启后需要重新获取登录链接，已有预约仍会恢复。

浏览与预约 ​

  1. 在页面顶部选择 profile，再选择游戏分区。
  2. 商品列表显示米游币价格、当前库存、下一批开放时间和数量。时间统一为北京时间，并显示倒计时；库存为零但官方有下一批时间时仍可预约。
  3. 打开商品详情，核对官方兑换条件；游戏奖励选择当前账号绑定的角色，实物商品选择米游社已有的收货地址。地址只显示脱敏姓名和手机号末四位。
  4. 勾选使用该 profile 的米游币兑换 1 件商品，再点击创建预约或立即兑换。
  5. 在“我的预约”查看状态、取消未提交的预约，或核对待确认结果。

未选定商品、未创建预约时不会自动兑换。创建预约不预扣米游币；成功兑换时由官方扣除。真实兑换仍取决于官方库存、等级、限购及验证要求，页面显示的条件以商品详情为准。

定时执行 ​

预约持久化保存在 data/coinShop/plans.json，不保存 Cookie 或设备凭据。到点前 15 秒检查登录态、设备、余额与兑换目标，随后等待目标时间提交。机器人的系统时钟需要正常同步。

同一账号的兑换按顺序执行，避免同一计划重复提交。重复预约同账号、同商品会被拒绝。价格或类型变化、绑定账号变化时停止，需重新预约；官方调整未来开放时间时会同步计划。错过原定场次超过 30 秒不补发请求，需重新预约。

官方明确返回未到兑换时间、系统繁忙等可重试结果时，在开放后 20 秒内每隔至少 500 毫秒尝试，最多 30 次；成功后立即停止。余额不足、限购、售罄和需要验证等结果停止执行，并通知发起者。

兑换提交后网络中断时，不能假定没有扣币，因此标记为“结果待确认”，不会自动重发。请先核对米游社兑换记录，再在页面确认“已兑换”或“未兑换”。机器人在请求提交过程中重启也按相同方式处理。

共用端口与独立部署 ​

全局配置的 coin_shop 字段：

yaml
coin_shop:
  enable: true
  mode: auto
  host: 127.0.0.1
  port: 18164
  path: /lotus/coin-shop
  public_url: ""
  session_hours: 8

  • auto：优先挂到 TRSS 的现有 HTTP 服务，不另占端口；没有共用服务时启用 host、port 指定的独立服务。
  • shared：只使用 TRSS 的共用端口，不提供共用服务时明确报错。
  • standalone：使用独立端口，便于单独反向代理。
  • path：网页和 API 的挂载路径。
  • public_url：本机配置中的外部访问地址，例如 https://your-domain.example/lotus/coin-shop/。留空时使用 TRSS 配置的地址或本机独立端口地址。域名和 frp 参数无需写入源码。

共用模式下，网页自身完成登录鉴权，处理自己的路径后直接返回，避免登录票据和会话 Cookie 被宿主通用请求日志记录。其他 TRSS 路由保持原处理方式。请求会校验来源与 CSRF 凭据，Cookie 使用 HttpOnly、SameSite；公网应通过 HTTPS 访问。

实现参考 ​

官方商城的商品、余额、地址和角色查询接口，以及商品兑换请求参数，参考了 MiyoQian 的商城实现。Lotus 使用自身的登录、设备、网页鉴权、持久化预约与调度，不调用第三方兑换服务。
